# swift-java resolve

**Framework**: Swift-Org/SwiftJavaDocumentation  
**Role**: Article

Download Java dependencies for use in Swift builds.

## Overview

`swift-java resolve` reads the Java dependencies declared in a [swift-java.config](./swiftjavaconfigfile.md) and fetches them, then writes a `<SwiftModule>.swift-java.classpath` file into the `--output-directory`.

`swift-java` commands search for `*.swift-java.classpath` files and assemble them into a classpath for Java operations; `wrap-java` uses that classpath when wrapping Java classes for Swift.

You can always use the command line `--help` to get additional guidance about the tool and available options:

```txt
> swift-java resolve --help

OVERVIEW: Resolve dependencies and write the resulting swift-java.classpath file

USAGE: swift-java resolve [--output-directory <output-directory>] [--input-swift <input-swift>] [--log-level <log-level>] [--config <config>] [--cp <cp> ...] --swift-module <swift-module> [<input>]

ARGUMENTS:
  <input>                 Additional configuration paths (swift-java.config)
                          files, with defined 'dependencies', or dependency
                          descriptors formatted as 'groupID:artifactID:version'
                          separated by ','. May be empty, in which case the
                          target Swift module's configuration's 'dependencies'
                          will be used.

OPTIONS:
  -o, --output-directory <output-directory>
                          The directory in which to output generated SwiftJava
                          configuration files.
  --input-swift <input-swift>
                          Directory containing Swift files which should be
                          extracted into Java bindings. Also known as
                          'jextract' mode. Must be paired with --output-java
                          and --output-swift.
  -l, --log-level <log-level>
                          Configure the level of logs that should be printed
                          (values: trace, debug, info, notice, warning, error,
                          critical; default: log level)
  --config <config>       A path to a custom swift-java.config to use
  --cp, --classpath <cp>  Class search path of directories and zip/jar files
                          from which Java classes can be loaded.
  --swift-module <swift-module>
                          The name of the Swift module into which the resulting
                          Swift types will be generated.
  -h, --help              Show help information.
```

### Example

You can use `swift-java resolve` explicitly on the command line:

```bash
swift-java resolve \
  --swift-module JavaCommonsCSV \
  -o .build/plugins/outputs/JavaCommonsCSV \
  "org.apache.commons:commons-csv:1.12.0"
```

Or, include dependency identifiers in gradle format: `<groupID>:<artifactID>:<version>` in `swift-java.config` configuration files, like so:

```json
{
  "dependencies": [
    "org.apache.commons:commons-csv:1.12.0"
  ]
}
```

This lets `swift build` resolve and fetch the Java dependencies automatically. Because fetching needs network access, which the SwiftPM sandbox blocks, you must pass `--disable-sandbox` when building such a package. See [SwiftPM Plugin](./swiftpmplugin.md) for more on the build plugin’s caveats here.

> 💡 **Tip**: See `Samples/JavaDependencySampleApp` for a fully functional showcase of this mode.
