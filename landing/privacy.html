Privacy Policy

Effective November 18, 2026

  • xdocs is a free, read-only search service over public developer documentation. It has no accounts, cookies, analytics or ads.
  • To answer a request, the server reads the tool arguments your AI client sends: search text, a page path or symbol name, and filters. It keeps none of them, except in its log when a call fails or is rejected as invalid.
  • Every request passes through our HTTPS proxy, which can log your IP address with the request's path and headers, but never its content. The MCP server itself holds your IP address in memory for rate limiting, usually for a few minutes, and logs it only if you go over the limit.
  • We never see your conversations, chat history, memory or files. We don't sell or share data, and we don't use it to train AI models.
  • The home page loads its fonts from Google Fonts, so Google sees your IP address when you open it.

Scope

This policy covers the hosted service at xdocs.dev: the MCP server at https://xdocs.dev/mcp, its /health endpoint, and the website at https://xdocs.dev. The code is open source. If you run your own copy, you operate it and this policy doesn't apply to it.

Your AI client (Claude, Cursor, VS Code or another) and its provider handle your conversations under their own privacy policies.

Who we are

xdocs is an independent project run by one developer ("we"). Contact: info@xdocs.dev. xdocs is not affiliated with, endorsed by or sponsored by Apple Inc. or Anthropic.

What we collect and why

Tool arguments

When your AI client calls a tool, the server receives the tool's arguments: search text, framework and platform filters, a page path or symbol name, and paging options. It uses them to search its own copy of the documentation, which runs on the same server, and returns the result. No query or reply is cached or stored once the reply is sent.

The server's log records arguments only when something goes wrong:

  • A call, or one of its steps, fails with an internal error (for example, while the search engine restarts). The log line holds the search text, page path or symbol name, so we can find and fix the failure.
  • A call or MCP message is rejected as invalid (for example, search text over 256 characters, or a word where a number is expected). The log line holds the rejected value; for a missing argument, the call's other arguments; for a malformed MCP message, its parameters.

The search engine doesn't record search text either. Its log has one line per request the server makes to it (time, method, path and status), never the search text or your IP address, and its usage telemetry is turned off.

IP addresses

  • Rate limiting. Each IP address may make 60 requests a minute; each of the published addresses that Claude and ChatGPT call connectors from, which all their users share, may make 1,000. To enforce this, the server keeps in memory the times of each address's requests from the last minute. Times older than a minute are dropped, and an address with no recent requests is removed at the next cleanup, which runs at most every 5 minutes while requests keep arriving (so usually within about 6 minutes; with no traffic at all, at the next request). All of them are cleared whenever the server restarts.
  • Going over the limit. For each request it refuses because the limit was reached, the server logs a line with the address and its request count.
  • Request log. For each request, the server logs the method, path (with any query string), HTTP version and status, and the address that connected to it: for requests made through https://xdocs.dev, that is our proxy's address, not yours. Each MCP request also gets a timestamped line naming its type (such as a tool call), without its arguments.
  • Our HTTPS proxy. Every request to xdocs.dev passes through our web server (Caddy), which handles HTTPS. Its log can record a request's time, your IP address, the path and the request headers, such as User-Agent; it always records a request it fails to pass on, for example during a redeploy of 10 to 20 seconds. By default it hides authorization headers and cookies. It never records the request body, which is where tool arguments travel.

If you use xdocs as a connector in Claude.ai, the Claude apps or ChatGPT, the requests come from Anthropic's or OpenAI's servers, so the IP address we see is theirs, not yours. From Claude Code, Cursor, VS Code or another client on your computer, it is the address of your network.

Client name and User-Agent

MCP clients send their name and version when they connect, and HTTP requests carry a User-Agent header. The server doesn't log or store either, except within a malformed MCP message (see Tool arguments) and in our proxy's log (above). Nothing about callers is ever shown publicly.

API keys

If we have given you an API key to lift the rate limit, the server checks it in memory and never logs it.

Email

If you email info@xdocs.dev, Cloudflare Email Routing forwards your message to the maintainer's mailbox. We keep it as long as we need it to answer you, and delete it if you ask.

Usage statistics

None. The server counts nothing per user, client or IP address beyond the one-minute rate-limit window, keeps no usage statistics and runs no analytics. The /health endpoint reports only facts about the index: its status, document and framework counts, and when it was last updated.

What we don't collect

  • No accounts or sign-in, and no names or email addresses unless you email us.
  • No conversations, chat history, memory or files. An MCP server receives only the tool arguments your client sends it.
  • No cookies, tracking pixels, fingerprinting or analytics, on the server or the website.
  • No selling or sharing of data, no advertising, and no use of your data to train AI models.

The website

xdocs.dev sets no cookies, uses no local storage and runs no analytics. The home page loads its fonts from Google Fonts (fonts.googleapis.com and fonts.gstatic.com), so your browser sends Google your IP address, browser details and the page's address; Google's privacy policy covers that. This privacy page loads nothing from third parties. The home page loads its skill text and its live status (/health) from xdocs.dev itself; those requests appear in our request log like any other. Links to GitHub, Buy Me a Coffee, Apple and Anthropic take you to those sites, under their own policies.

Security

  • xdocs.dev is served over HTTPS; plain-HTTP requests are redirected to HTTPS.
  • Logs stay on our server, which only the maintainer can access, and are never uploaded or shared.
  • The search index holds only public documentation, nothing about users.

Your rights

Depending on where you live (for example under the EU or UK GDPR, Canada's PIPEDA or California's CCPA), you can ask what personal data we hold about you, and ask us to correct or delete it or to stop using it. Since there are no accounts, we can find log lines only if you tell us your IP address and roughly when you used xdocs. Email info@xdocs.dev and we'll reply within 30 days.

Under the GDPR, we rely on our legitimate interests: running the service, protecting it from abuse (the rate limit) and fixing failures (the error logs). We don't sell or share personal information as the CCPA defines those terms, and we don't collect sensitive personal information. You can also complain to your data-protection authority; in Canada, that is the Office of the Privacy Commissioner.

Children

xdocs is a tool for software developers and isn't directed at children under 13 (under 16 in the EU). We don't knowingly collect children's personal data.
